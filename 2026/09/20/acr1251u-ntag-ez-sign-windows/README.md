# OEM版ACR1251U（072F:222D）のファームウェアを書き換えて非接触側を動かす

ジャンクで手に入れたACS ACR1251U-M3（USB `072F:222D`、ファームウェア `ACR1251U_V541.00`）が、リーダーとしては認識されるのにカードを一切検出しない。NTT版の配布ファームで書き換えたところ、正規の `072F:2229` / `ACR1251U_V431.2` になって動くようになった。

記事: [JA](https://www.lilting.ch/articles/acr1251u-ntag-ez-sign-windows)

Firmware recovery notes for an OEM ACS ACR1251U (USB `072F:222D`) whose contactless front end never powers any card. The stock vendor updater rejects the device by firmware-version family; patching one byte in its IL lets the update proceed.

> [!WARNING]
> ファームウェアの書き換えは不可逆で、失敗すればリーダーは使えなくなる。ここに書いてあるのは、動かない個体を捨てる前に試した手順で、動いている個体に適用する理由は無い。自己責任で。

## 症状

| 観測点 | 値 |
|---|---|
| USB | `VID_072F&PID_222D&REV_0541` |
| USBが名乗る製品名 | `ACR122U for NFC` |
| 筐体ラベル | `SO-SOL122-D` / `P/N: ACR1251U-M3` |
| ファームウェア | `ACR1251U_V541.00` |
| PC/SCのカード状態 | カードの有無に関係なく `PRESENT + UNPOWERED` |
| ATR | カードの有無に関係なく `3B 00` |
| APDU応答 | すべて `SW=6300` |
| ブザー | 直接鳴らす指示を出しても無音 |
| LED | カードの有無に関係なく点滅し続ける |

カードを載せていなくても同じ値を返すので、「カードを検出している」という情報はここから取れない。スマートフォンをリーダーに載せても反応しないので、13.56MHzの電波が物理的に出ていない。

`072F:222D` はacsccidの対応リーダー定義で次のように登録されている。ACR122Uを名乗るACR1251U-A2のOEM品になる。

```
# ACR1251U-A2
0x072f:0x222d:ACS ACR122U
```

## 前提

- Windows（検証はWindows 11 Home 10.0.26200）
- ACS Unified PC/SC Driver。`222D` はINFに無いので手動で当てる必要がある
- 同型の個体がもう1台あると、比較対象として残せる

## 手順1 ACS純正ドライバを手で当てる

ACS公式のドライバ（ACS Unified PC/SC Driver）をインストールする。`222D` はINFに無いので、この時点ではデバイスに当たらない。

デバイスマネージャーで対象を右クリックし、ドライバーの更新 → コンピューターを参照 → 一覧から選択 → **「互換性のあるハードウェアを表示」のチェックを外す** → 製造元「Advanced Card Systems Ltd.」→ モデル **「ACR1251 CL Reader PICC」**（PID 2229 のACR1251U-A2用）を選ぶ。互換性の警告は出るが、署名は壊れないのでインストールできる。

これでベンダー独自のエスケープコマンドが通るようになる。Windows標準のUsbccidドライバのままだと `ERROR_INVALID_FUNCTION` で弾かれる。

確認には [`pcsc_probe.ps1`](pcsc_probe.ps1) を使う。

```
ACR1251 Get Firmware  [E0 00 00 18 00]
    -> E1 00 00 00 10 41 43 52 31 32 35 31 55 5F 56 35 34 31 2E 30 30   |.....ACR1251U_V541.00|
```

## 手順2 ファームウェアと書き換えツールを入手する

ACS公式はファームウェアも書き換えツールも配布していない。問い合わせ経由になる。

NTTコミュニケーションズが公的個人認証サービス向けにOEM版ACR1251のファームウェア一式を公開しており、登録なしで取得できる。中身はACS純正の「ACR1251 FW Update Tool」と、ファームウェア本体の `Patch/Patch.hex`。

| 版数 | 配布ページ |
|---|---|
| 431.2（CL） | <https://www.ntt.com/business/services/application/authentication/jpki/download7.html> |
| 713.0 / 721.1（DI） | <https://www.ntt.com/business/services/application/authentication/jpki/download8.html> |

ツールのexeは3種ともバイト単位で同一で、機種差は `InitFile.ini` と `Patch/` だけになる。

本手順では **431.2（CL版）** を使った。手元の個体が返すRF系レジスタの値が、CL版の初期化列 `Patch/Init.txt` と完全一致していたため。

| 設定 | CL 431.2が流す値 | 手元の個体（書き換え前） |
|---|---|---|
| `2F` | `11 85 85 85 85 A5 A5 A5 A5 69 …` | 完全一致 |
| `3F` | `2F 55 69 3F 2F 55 69 3F` | 完全一致 |

## 手順3 なぜ弾かれるのかを確認する

ツールを起動してリーダーを選び、更新を押すと「Reader検索エラー」で止まる。通常モードでもブートローダーモードでも同じ。

更新処理を読むと、原因はリーダー名ではなく**ファームウェアの版数**だった。ツールは.NETアセンブリなので、ILSpyなどで中を確認できる。

判定はこうなっている。

1. リーダーへ `E0 00 00 18 00` を投げる
2. 応答から機種名（`ACR1251`）と版数文字列（`541.00`）を切り出す
3. 版数文字列の先頭3桁を16進として読む（`541` → `0x541`）
4. その値と `0x700` の論理積を取り、対象機種ごとに決まった値と一致するか見る

| 対象 | 要求される値 | 該当する版数 |
|---|---|---|
| C4版 | `0x700` | 7xx系 |
| M2版 | `0x400` | 4xx系 |

`0x541 & 0x700 = 0x500` なので、どちらの系統にも該当せず門前払いされる。`InitFile.ini` の `Reader#ACR1251CL-NTTCom#` は内部でM2扱いになるため、要求されるのは4xx系になる。

版数判定の直後に「通常モードのリーダーを書き換えモードへ切り替える」コマンドを必ず送るので、あらかじめブートローダーモードで挿しておいても通らない。

AES鍵はexe内の定数で、個体ごとの秘密ではない。認証段は素通りする。

## 手順4 版数ゲートを1バイト書き換える

該当のILは `ldc.i4 0x700` → `and` → `ldc.i4 0x400` の並びになる。バイト列で表すと次のとおり。

```
20 00 07 00 00   ldc.i4 0x700
5F               and
20 00 04 00 00   ldc.i4 0x400     ← この 04 を 05 にする
```

M2側のゲートを手元の版数（5xx系）に合わせる。C4側は `20 00 07 00 00 5F 20 00 07 00 00` で別パターンなので触らない。

[`patch-fw-gate.ps1`](patch-fw-gate.ps1) がこれを行う。元のexeは変更せず、複製に対して当てる。

```powershell
.\patch-fw-gate.ps1 -ToolDir "<ACR1251CL_FW431.2を展開したディレクトリ>" -OutDir "<出力先>"
```

検証した個体では、該当は1箇所（オフセット `0x003927`）だけだった。ファイルサイズは変わらない。

| ファイル | SHA-256 |
|---|---|
| オリジナル | `646196FE6D1B5AE7691846A62E9655BEFF92BD5AC01B3D00CBAAA3B713E2A876` |
| ゲートを外した版 | `73B4A87238174336D1BA1846A0E6B3F1FF9238B46B20FBB36D88E3944204AE96` |

## 手順5 書き換える

リーダーは**通常モード**で挿す（スイッチを押さない）。ツール自身が書き換えモードへ切り替える。

パッチ版のツールを起動し、再表示を押して `ACS ACR1251 CL Reader PICC 0` を選び、更新を押す。

```
現在のバージョン： 541.00
更新後： 431.2
更新しますか？
```

実機から読んだ版数が出ていれば、ゲートは通っている。はいを押すと、書き換えモードへの切り替え、認証、書き込みまで進む。**途中でUSBを抜かない。**

なお筐体裏のスイッチを押しながら挿すとブートローダー（`072F:220B`、`ACR1281 USB FW_Upgrade v100`）で起動する。書き換えに失敗してもここへは入れるので、正しいファームウェアがあればやり直せる。

## 結果

| 項目 | 書き換え前 | 書き換え後 |
|---|---|---|
| USB PID | `222D`（名前のないOEM枠） | `2229`（正規のACR1251U-A2） |
| ファームウェア | `ACR1251U_V541.00` | `ACR1251U_V431.2` |
| PICC動作パラメータ | `07`（Type A / B / Topaz） | `1F`（FeliCa 212 / 424まで） |
| 自動PICCポーリング | `8F` | `8B` |
| シリアル番号 | 空 | 値が返る |
| カード状態（カードなし） | `PRESENT + UNPOWERED` | `EMPTY` |
| LED | 常に点滅 | カード検出で点灯、待機でゆっくり点滅 |

書き換え前は設定を書き込んでも電源を入れ直すと既定値へ戻ったが、書き換え後は保持される。

NTAG215、マイナンバーカード（ISO 14443-4）、NFC電子ペーパー（Santek EZ Sign）のいずれも読めるようになった。EZ SignはSantek公式のWindowsアプリがPC/SC経由で動くため、このリーダーでそのまま表示を書き換えられる。

## 収録スクリプト

いずれもPowerShellから `winscard.dll` を直接叩く。外部モジュールは不要。

| ファイル | 用途 |
|---|---|
| [`pcsc_probe.ps1`](pcsc_probe.ps1) | ファームウェア版数、PICC動作パラメータ、ポーリング設定、アンテナ状態を読む |
| [`pcsc_state.ps1`](pcsc_state.ps1) | カードの有無とATRを1回だけ取る。幽霊カードの確認用 |
| [`pcsc_watch.ps1`](pcsc_watch.ps1) | 15秒間カードの状態変化を監視する |
| [`pcsc_read.ps1`](pcsc_read.ps1) | ATR、UID、ATS、NTAGのページを読む |
| [`pcsc_write.ps1`](pcsc_write.ps1) | NTAGへNDEFのURIレコードを書いて読み戻す |
| [`patch-fw-gate.ps1`](patch-fw-gate.ps1) | 版数ゲートを1バイト書き換える |

ファームウェア本体と書き換えツールは再配布しない。上記のNTTの配布ページから取得すること。
